# Права пользователей и пространств

Справочник по группам, codename-правам и области данных в Materials DB.

**Источник в коде:** `apps/workspaces/permissions.py`  
**Связанные документы:** [Workspaces & RBAC](workspaces-rbac.md) · [Architecture index](index.md)

---

## Группы и участники

| Уровень | Как определяется | Где действует |
|---------|------------------|---------------|
| **Admin** | `user.is_superuser` | Все пространства; не требует групп |
| **Участник пространства** | Есть хотя бы одна `WorkspaceGroupMembership` | Только в назначенных пространствах |
| **Группа** | `WorkspaceGroup` с набором codename в `permissions` | Внутри одного workspace |

Пользователь может состоять в **нескольких группах** одного пространства. Эффективные права — **объединение (union)** прав всех его групп.

Встроенные группы «Менеджер» и «Оператор» создаются при создании пространства (`ensure_default_groups`). Их права редактируемы, удаление запрещено.

Admin создаёт пользователей, пространства и назначает группы. Пользователь с `workspace.manage_members` добавляет участников в группы, которые сам может назначать (без привилегированных прав). CRUD групп — `workspace.manage_settings`.

---

## Встроенные группы (шаблоны)

| Группа | Ключевые права |
|--------|----------------|
| **Менеджер** | `manage_settings`, `manage_members`, полный CRUD материалов/образцов/сканов, публикация |
| **Оператор** | Просмотр и работа с материалами, образцами, сканами, тегами; без администрирования |

Настраиваемые группы могут включать любой поднабор codename из `ALL_WORKSPACE_PERMISSIONS`. Группа обязана содержать `workspace.view`.

## Матрица codename-прав

Проверка: `has_workspace_perm(user, workspace, codename)`.  
Admin автоматически имеет **все** права из таблицы.

| Codename | Описание | Менеджер (builtin) | Оператор (builtin) |
|----------|----------|:------------------:|:------------------:|
| `workspace.view` | Вход в пространство, просмотр данных | ✓ | ✓ |
| `workspace.manage_settings` | Настройки и группы | ✓ | — |
| `workspace.manage_members` | Участники пространства | ✓ | — |
| `material.view` | Просмотр материалов | ✓ | ✓ |
| `material.create` | Создание материалов | ✓ | ✓ |
| `material.edit` | Редактирование материалов | ✓* | ✓* |
| `material.delete` | Удаление материалов | ✓ | — |
| `material.publish` | Публикация / видимость материала | ✓ | — |
| `structure.view` | Просмотр типов структур и данных | ✓ | ✓ |
| `sample.view/create/edit` | Образцы | ✓ | ✓ |
| `sample.delete` | Удаление образцов | ✓ | — |
| `scan.view/create/edit` | Сканы | ✓ | ✓ |
| `scan.delete` | Удаление сканов | ✓ | — |
| `property.view` | Просмотр справочника свойств | ✓ | ✓ |
| `tag.view/create/edit/delete` | Теги пространства | ✓ | ✓ |
| `user.manage` | Пользователи (admin UI) | — | — |

\* Редактирование материала только если `material.is_editable_in(active_workspace)`.

Глобальные теги: только admin. Справочник свойств: CRUD в UI только у admin.

## Делегирование назначения групп

| Право в группе | Кто может назначать такую группу |
|----------------|----------------------------------|
| Обычные права (material.*, sample.*, …) | Admin или `manage_members` |
| `manage_settings`, `manage_members`, `user.manage` | Только admin |

Пользователя с группой, содержащей привилегированные права, может изменять только admin (`can_manage_membership`).

## Область данных

Без изменений: материалы по `home_workspace` + публикация; образцы/сканы/теги — по `workspace`; Property и StructureType — глобально.

---

## Примечания

1. Без активного пространства (session `active_workspace_id`) — redirect на `/workspaces/select/`.
2. Участник без групп с `workspace.view` не видит пространство в picker.
3. Codename проверяются в контексте активного workspace; admin bypass через `is_superuser`.
