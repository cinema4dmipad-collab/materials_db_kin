# Права пользователей и пространств

Справочник по ролям, codename-правам и области данных в Materials DB.

**Источник в коде:** `apps/workspaces/permissions.py`  
**Связанные документы:** [Workspaces & RBAC](workspaces-rbac.md) · [Architecture index](index.md)

---

## Роли

| Роль | Как определяется | Где действует |
|------|------------------|---------------|
| **Admin** | `user.is_superuser` | Все пространства; не требует membership |
| **Менеджер** | `WorkspaceMembership.role = manager` | Только в пространствах, где пользователь — участник |
| **Оператор** | `WorkspaceMembership.role = operator` | Только в пространствах, где пользователь — участник |

Admin создаёт пользователей, пространства и назначает менеджеров. Менеджер управляет настройками своего пространства и добавляет **только операторов**.

## Область данных по пространствам

| Сущность | Привязка к workspace | Видимость |
|----------|----------------------|-----------|
| **Материал** | `home_workspace` | Свои + опубликованные (`private` / `selected_workspaces` / `all_workspaces`) |
| **Тег** | `workspace` | Только своё пространство |
| **Образец** | `workspace` | Только своё пространство |
| **Скан** | `workspace` | Только своё пространство |
| **Вложения** (образец / материал) | `workspace` | Только своё пространство |
| **Свойство** (справочник) | — | Глобально, во всех пространствах |
| **Тип структуры** | — (общий каталог) | Глобально, во всех пространствах |
| **Пользователь / membership** | membership per WS | По назначенным пространствам |

## Материалы: редактирование и публикация

| Ситуация | Просмотр | Редактирование |
|----------|:--------:|:--------------:|
| Материал в своём `home_workspace` | ✓ | ✓ (manager / operator) |
| Опубликованный чужой материал в активном WS | ✓ | — (read-only) |
| Admin в любом WS | ✓ | ✓ |
| Публикация (`visibility_mode`, список WS) | — | manager+ в home WS |

## Примечания

1. Без выбранного активного пространства (session `active_workspace_id`) пользователь перенаправляется на `/workspaces/select/`, кроме admin с особыми маршрутами.
2. Codename-права проверяются **в контексте активного workspace**. Admin bypass — через `is_superuser`.
3. Типы структур дополнительно проверяются через `can_manage_structure_types()` (только admin), даже если codename когда-либо расширят для manager.
