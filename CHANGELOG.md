## [Unreleased]

### Added

- Дашборд: дата и день недели, блок «Требуют внимания», сводка по пространству, ленты недавних материалов и образцов, заглушка под будущую аналитику.
- Flash-сообщения: плавное появление и автоматическое скрытие (ошибки остаются до ручного закрытия).
- Импорт материалов: нераспознанные числовые ячейки (например «160(+10)/100(±10)») блокируют запись; на шаге «Запись» техник может исправить значения вручную или проигнорировать их — после этого импорт применяется сразу (для игнора — модальное подтверждение).
- Списки: активные фильтры-чипы можно снять крестиком (без сброса всей формы фильтров).
- Список материалов: «Выгрузить в Excel» для выбранных строк одного типа структуры (иначе подсказка); в файле — поля структуры, свойства справочника и только заполненные метаданные, без тегов, автора и даты создания.
- Выгрузка Excel: скачивание через fetch с проверкой ZIP/XLSX — ошибки больше не сохраняются как битый `.htm`/«excel».
- Выгрузка Excel: исправлен обрыв скачивания в Chrome (ранний revoke blob URL); добавлен запасной POST в hidden iframe.
- Выгрузка Excel: скачивание через обычный form POST в новую вкладку (без blob/fetch) — обход сбоев Chrome на проде.
- Импорт: строки без названия (пустая ячейка в колонке «Название», часто пустая «Марка») автоматически пропускаются и не блокируют запись остальных.
- Форма материала: производитель / доступность / технология вынесены в блок «Справочные свойства» и добавляются по кнопке «Добавить» (пустые поля больше не висят всегда); на карточке пустые справочники скрыты.

### Fixed

- Импорт: создание неизвестных значений справочников выполняется в одной транзакции с материалами (при ошибке записи «сироты» в справочнике не остаются).
- Импорт: значения вида `900/2200 Н/50мм` не принимаются молча как одно число — уходят в ручную правку.

## [0.2.0] - 2026-07-22

### Added

- План и ADR: workspaces, RBAC (admin/manager/operator), GitLab-подобный sidebar ([docs/architecture/workspaces-rbac.md](docs/architecture/workspaces-rbac.md)).
- Приложение `apps.workspaces`: модели Workspace/Membership, middleware, login/logout, выбор пространства, sidebar, права manager/operator, UI администрирования пользователей и настроек WS.
- Зависимость `django-guardian`; команда `migrate_to_workspaces` для переноса prod-данных в Legacy WS.
- Форма материала: модальный выбор типа структуры; sticky-кнопки сохранения на длинных формах.
- Автоподстановка нового свойства в форму материала после создания из справочника.
- Образцы наследуют параметры структуры материала (просмотр и форма).
- Ссылки на материалы в пространстве (`WorkspaceMaterialLink`) вместо полного клонирования; кнопка «Добавить в пространство».
- Создание материала «на основе»: подстановка полей, свойств, параметров структуры, слоёв и тегов из шаблона (без образцов и файлов); шаблоном может быть любой материал пространства.
- Профиль пользователя: редактирование имени, e-mail и смена пароля; создание учётных записей — только администраторам.
- Тип свойства «Материал»: значение — ссылка на другой материал (выбор через picker при добавлении свойства к материалу).
- Тип свойства «Выбор из списка»: варианты задаются в справочнике свойства; на форме материала значение выбирается из стилизованного списка; в типе структуры такое свойство добавляется как `ChoiceField` (не как строка) с сохранением вариантов.
- После создания SQL-таблицы типа структуры можно добавлять новые поля (колонки); удаление и изменение существующих полей запрещены.
- Теги: цвет (#RRGGBB), описание, архив; scoped-названия `область::значение` с взаимоисключением по области; GitLab-подобный вид меток.
- Числовые свойства материалов и образцов: режимы «точное», «диапазон» и «± погрешность»; в справочнике — поле «знаков после запятой».
- Десятичные поля типов структур: те же режимы значения (точное / диапазон / ±); команда `migrate_structure_decimal_ranges` для существующих таблиц.
- Импорт материалов: CLI `import_materials` и UI-мастер с обязательным типом структуры, маппингом колонок в поля структуры (SQL) и доп. свойства справочника (без автосоздания Property), политикой уникальности, черновиком и профилями маппинга.
- Импорт: значения `material_link` и полей структуры `MaterialLink` — по коду, уникальному названию или UUID (в т.ч. на материалы из того же файла).
- Импорт XLSX: объединённые ячейки разворачиваются — значение из левой верхней ячейки копируется во все строки/столбцы объединения.
- Импорт: режим **построчной** записи выбирается сразу после сопоставления колонок (равноправно с пакетным черновиком).
- Импорт: из ячеек вроде `4050/ 50мм` и `12,5 мм` извлекается число (единицы / ширина полоски отбрасываются).
- Импорт: запись вида `0,27+0,035` / `12+1 /м` читается как ± допуск (как в больших таблицах Excel без символа ±).
- Откат последнего импорта: кроме `DEBUG` можно включить `IMPORT_BATCH_UNDO=true` на стенде.
- Поле `Material.import_source_filename` и фильтр «Источник импорта» в списке материалов (материалы из конкретного файла импорта).
- Импорт: демо-файлы большой таблицы Excel/CSV (`materials_wide_demo`) и ссылки скачивания на шаге загрузки.
- Групповое удаление в списке материалов: кнопка «Выбрать», чекбоксы, подтверждение и удаление выбранных (с учётом прав и защиты слоёв).
- Групповое удаление также в списках тегов, образцов, свойств и справочников материалов (та же кнопка «Выбрать»).
- Подтверждение удаления — диалог на той же странице (вместо отдельной страницы подтверждения), в т.ч. для группового удаления.
- Глобальные справочники материалов (производитель, доступность, технология): поля на материале, фильтры списка, цели импорта; UI «Справочники» и админка.
- Импорт: опция «создавать неизвестные значения справочников» с отчётом и защитой от дубликатов (имя/код).

### Changed

- `Material.name`: лимит длины увеличен с 200 до 1000 символов (длинные названия-укладки из больших таблиц Excel).
- В типе структуры убрана кнопка «Ссылка на материал»: ссылка на материал добавляется только через свойство справочника (`material_link`) в пикере «Добавить».
- Material/StructureType/Sample/Scan: поля `home_workspace`/`workspace`, видимость и фильтрация по активному пространству; код уникален в пределах WS.
- Карточка свойств: единица в отдельной колонке «Ед.» рядом со значением (значение справа, единица слева), блок прижат к названию свойства.
- При создании свойства из формы материала черновик формы сохраняется и восстанавливается после возврата.
- «Создать на основе»: код и название копируются из шаблона без префикса; дубликат кода в пространстве и среди общих материалов блокируется при сохранении.
- Карточка материала: ссылка «Открыть материал» вместо «Открыть образец».
- Точность десятичных полей структуры по умолчанию — 4 знака после запятой.
- Общие и ссылочные материалы: образцы и вложения показываются из домашнего пространства материала (readonly).
- Формы входа и администрирования пользователей: единый Bootstrap-шаблон полей.
- Цвет типа структуры — свободный hex с палитрой (вместо фиксированных tone-классов).
- Теги: inline-редактирование на карточках материала, образца и скана (только в своём пространстве); цвет общих тегов на бейджах; назначение тегов в workspace сущности.

### Fixed

- Импорт: при ошибках валидации на шаге черновика запись запрещена; доступна кнопка «Исправить сопоставление» (возврат к маппингу без перезагрузки файла).
- Импорт: без сопоставления «Название» нельзя собрать черновик; строки без названия дают ошибку валидации (раньше тихо пропускались).
- Импорт `LocalizedFloatField` / `LocalizedDecimalField` в формах структуры.
- Синхронизация диаграммы слоёв композита при добавлении последнего слоя.
- Отображение свойств образца при смене материала через JSON API.
- 404 при открытии образца общего/legacy-материала (`home_workspace`/`workspace` = NULL).
- Предупреждение при создании материала с названием, совпадающим с уже опубликованным общим.
- При «создать на основе» параметры структуры шаблона не подставлялись из-за ложной смены типа структуры.
- HTML-ссылка «Общие» в сводке ошибок валидации отображалась как текст.

## [0.1.2] - 2026-06-17

### Added

- Debug: хэш git-коммита рядом с версией приложения.
- Форма материала: сводка ошибок валидации по разделам формы, свойств и слоёв.
- Django admin: ссылка на Debug в шапке для staff-пользователей.

### Changed

- Схема слоёв композита: высота диаграммы пропорциональна числу слоёв (максимум 320px).

### Fixed

- Горячие клавиши Del и Ins в таблице слоёв композита.
- Ложные ошибки уникальности при копировании слоёв (перенумерация до проверки формы).
- Валидация неполных строк слоя: понятные сообщения об обязательных полях.

## [0.1.1] - 2026-06-17

### Added

- Страница Debug: ссылки на админку S3 (Filer, Master, SeaweedFS Admin) и прокручиваемый список логов.
- Форма тегов: chip-интерфейс, фильтрация существующих тегов при вводе.

- Слои композита: компактный выбор материала без дублирующей кнопки «Выбрать».

### Fixed

## [0.1.0] - 2026-06-17

### Added

- Модуль сканов и образцов с хранением файлов в S3 (SeaweedFS).
- Динамические таблицы структур материалов (SQL + админка Django).
- Связи материалов со слоями и структурными таблицами.
- Теги, фильтры и поиск в интерфейсе списков.
- FAQ-раздел.
- Логотип и обновлённая Bootstrap-вёрстка.
- Production Docker Compose для Dokploy (`docker-compose.prod.yml`).
- GitLab CI/CD: тесты, сборка образа, manual deploy staging/production.
- Compose для S3-хранилища (`docker-compose.storage.yml`).

### Changed

- Рефакторинг моделей структур: удалены legacy EAV-модели, улучшены формы.
- Упрощён prod compose под Dokploy (образы через `WEB_IMAGE` / `NGINX_IMAGE`, без build на сервере).
- Обновлены цвета и стили UI.

### Fixed

- Восстановлена установка зависимостей через Poetry в Dockerfile.
- Сборка web-образа из Dockerfile, когда `WEB_IMAGE` не задан.
- Пропуск docker build при redeploy в Dokploy.
- Подключение SeaweedFS к `dokploy-network` для доступа Django к S3.

### Security

- Безопасная конфигурация через переменные окружения (`SECRET_KEY` обязателен при `DEBUG=False`).
