## [Unreleased]

### Changed

- Форма скана в веб-интерфейсе: вручную загружается только HDF5; превью B-скана-XZ / B-скана-YZ / C-скана задаются через API (KeenetiX).
- Карусель превью скана листает только загруженные виды (пустые B/C не показываются стрелками).

### Added

- Слои композита: при выборе материала слоя подставляется его параметр «Толщина» (поле структуры или свойство справочника), если толщина слоя не зафиксирована.
- Списки: клик по заголовку колонки сортирует таблицу по возрастанию/убыванию — материалы и образцы (код, название, тип/материал, дата), таблица материалов типа структуры (название, код и значения свойств). Пустые значения всегда в конце.
- Образцы: импорт CSV/XLSX тем же мастером, что у материалов (`/samples/import/`). На шаге настройки выбирается материал; в сопоставление попадают поля его структуры, свойства, описание, тип объекта и теги.
- Образцы: поле «Описание» на форме и карточке; поиск по описанию в списке и API.
- API v1: `GET /api/v1/scans/options/` — методы (эхо/теневой/иммерсивный) и поля превью для диалога сохранения в KeenetiX; create/update принимают `preview_b_xz` / `preview_b_yz` / `preview`.
- API v1: `PUT /api/v1/scans/{id}/` — замена HDF5 (и опционально превью/метаданных) для кнопки «Обновить скан» в KeenetiX (`scan.edit`).
- Превью отдаётся через приложение (`/preview/`, API `…/preview/`), а не прямым URL S3 — иначе в браузере пусто при SeaweedFS.
- Вложения у материалов, образцов и сканов: оригинал + миниатюра первой страницы (PNG) в списке; Word→PDF через LibreOffice, затем рендер; Excel — иконка; вкладка «Файлы» на карточке скана.
- Списки файлов и сканов: плиточный вид (как Google Drive) — превью, название, кто загрузил и дата; действия в меню ⋮.
- Плитки вложений: под превью показываются до 2 строк описания файла (полный текст при наведении); без описания блок скрыт.
- Числовые поля: значение «0 знаков после запятой» больше не подменяется на 2 (`0 or default` → default).
- Диагностика структур: ловит лишние SQL-колонки, поля без свойства в справочнике и типичный drift «переименовали в метаданных, таблицу не обновили»; кнопка починки `RENAME COLUMN`.

### Added

- Вложения: превью первой страницы для PPTX/PPT/ODP (LibreOffice Impress → PDF → PNG); в Docker — `libreoffice-impress-nogui`.
- Вложения: добавление файла через отдельную форму; кнопка **«Добавить»** в шапке вкладки «Файлы».
- Справочник: вкладка **Группы** рядом со свойствами (`/properties/groups/`) — общие на всю систему; просмотр по праву «Свойства», создание/правка — администраторам; на карточке материала доп. свойства сгруппированы по группам.
- Справочник свойств: нельзя удалить свойство, привязанное хотя бы к одному материалу (одиночное и групповое удаление).
- Структуры: мастер **переноса материалов** между типами (`/structures/migrate/`) — сопоставление полей в конструкторе как у импорта (drag-and-drop), все поля целевой структуры включая legacy ForeignKey/MaterialLink; одинаковые имена подставляются автоматически; опция удаления исходного типа после переезда.
- Структуры: **диагностика нормализации** (`/structures/diagnostics/`) — связи материалов↔SQL, колонки, «сироты», общие строки, дрейф `is_created`.
- Слои композита: кнопка **Расчёт** делит целевую Σt поровну; замочек у толщины фиксирует слой при пересчёте (`thickness_locked`).
- Слои композита: галочка **Симметричный** — в таблице первая половина (при нечёте последний = центр), зеркало в превью и на карточке; под слоями **+ N симметричных слоёв**, счётчик `8 сл. (+ N сим. слоёв)`, пунктир по плоскости симметрии.
- Превью укладки: режим легенды **Материал / Толщина / Угол армирования**; для толщины — градиент синий→белый→красный по min/max слоёв, для угла — фиксированная шкала **−90°…+90°**. Подписи слоёв справа от цветной колонки; высота полосы пропорциональна толщине слоя, тонкие слои не сжимаются ниже строки подписи. Формула схемы армирования только в синем блоке Σt, не в панели стека.
- Материалы: у кнопки **Создать** выпадающий пункт **Создать на основе…** (список материалов, дашборд, материалы типа структуры) — быстрый выбор образца без захода в пустую форму.
- Образцы: параметры структуры можно редактировать — подстановка с материала, сохранение в собственной SQL-строке образца (материал не меняется); при смене материала — новая подстановка.
- Слои композита: после заполнения укладки показывается **схема армирования** в нотации пар слоёв, как в таблице образцов: `(0/0)8`, `(0/90)4/(90/0)4`, `((0/90)/(+45/-45))2/((-45/+45)/(90/0))2`.
- Форма материала: подсказка по слоям (выбор строк, Del/Ins, «Расчёт», «Симметричный») перенесена в «?» у заголовка блока.

### Fixed

- Слои композита: тонкие полосы схемы укладки больше не схлопывают подписи (`#4`/`#13`) — у строки минимальная высота под текст.
- Тип структуры: свойства с тем же названием, что уже в списке, нельзя добавить повторно (в т.ч. `matrix` / `matrix_mat`); защита от двойного клика «Добавить»; после «Создать свойство» новое поле подставляется само, без дубля при возврате черновика.
- Слои композита: исправлен 500 при добавлении второго слоя (ложный unique по `layer_number` из‑за UUID до INSERT + `add_error` на MaterialForm).
- Числовые поля структуры при создании материала берут точность из справочника свойств (по имени колонки), а не всегда 2 знака; метаданные поля и SQL DECIMAL при необходимости подтягиваются. Синхронизация точности больше не падает 500 на форме материала, если SQL-таблица уже создана.
- Напоминание «Создать таблицу?» показывается только сразу после создания нового типа, а не при каждом заходе на черновик (в т.ч. после удаления SQL-таблицы).
- Сетка материалов типа структуры: убраны зазор и обрезка заголовков у липких колонок «Название»/«Код» (ширина и `left` снова совпадают).
- После удаления SQL-таблицы тип остаётся черновиком с полями: подсказки в UI, понятная ошибка при повторном добавлении тех же имён, черновик формы в sessionStorage разделён по типу (create/edit).
- Список материалов типа структуры: CTA **«Создать материал»** (с предвыбранным типом), ссылки на карточку материала вместо SQL-записи.
- Тип структуры: можно удалить **черновик** (без SQL-таблицы); добавление новых полей к созданной таблице — обязательность и восстановление черновика формы без сброса id строк.
- Числовые свойства материала (например плотность): при сохранении/переименовании значение больше не затирается пустым полем режима «±».
- Админка типов структур: `format_html` без аргументов больше не падает на Django 5+ («Таблица создана»).

## [0.3.0] - 2026-08-07

### Added

- HTTP API v1 (django-modern-rest): PAT в профиле, `Authorization: Bearer`, workspace через `X-Workspace-Id`; GET workspaces/materials/samples/scans (`search` по code/name у samples); POST скан к образцу; stream download HDF5 (**503** без S3/SeaweedFS). См. `docs/api/README.md` и Postman-коллекцию.
- Сканы: кнопка «Открыть в KeenetiX» на карточке и в списках (через desktop channel / API, без протокола `keenetix://`).
- Резервное копирование PostgreSQL: страница «Администрирование → Бэкапы» (суперпользователь), автокопирование по расписанию на том `/backups`, ручной дамп в браузер, **восстановление из загруженного `.dump`**; сервис `backup-cron` в Docker Compose. Файлы SeaweedFS не входят в бэкап.
- Бэкапы: интервал автодампа в днях (по умолчанию ежедневно); удаление файлов дампов с тома `/backups` из UI.
- Дашборд: дата и день недели, блок «Требуют внимания», сводка по пространству, ленты недавних материалов и образцов, заглушка под будущую аналитику.
- Flash-сообщения: фиксированный оверлей поверх страницы (не сдвигают контент), плавное появление и автоскрытие (ошибки — до ручного закрытия).
- Импорт материалов: нераспознанные числовые ячейки (например «160(+10)/100(±10)») блокируют запись; на шаге «Запись» техник может исправить значения вручную или проигнорировать их — после этого импорт применяется сразу (для игнора — модальное подтверждение).
- Списки: активные фильтры-чипы можно снять крестиком (без сброса всей формы фильтров).
- Список материалов: «Выгрузить в Excel» для выбранных строк одного типа структуры (иначе подсказка); в файле — поля структуры, свойства справочника и только заполненные метаданные, без тегов, автора и даты создания.
- Выгрузка Excel: скачивание через fetch с проверкой ZIP/XLSX — ошибки больше не сохраняются как битый `.htm`/«excel».
- Выгрузка Excel: исправлен обрыв скачивания в Chrome (ранний revoke blob URL); добавлен запасной POST в hidden iframe.
- Выгрузка Excel: скачивание через обычный form POST в новую вкладку (без blob/fetch) — обход сбоев Chrome на проде.
- Импорт: строки без названия (пустая ячейка в колонке «Название», часто пустая «Марка») автоматически пропускаются и не блокируют запись остальных.
- Форма материала: производитель / доступность / технология вынесены в блок «Справочные свойства» и добавляются по кнопке «Добавить» (пустые поля больше не висят всегда); значения выбираются через choice-picker; на карточке пустые справочники скрыты.
- Импорт: выбор типа структуры — та же модалка, что в форме материала (без варианта «без типа»).
- Импорт: при одной строке заголовков (без групп колонок) поля «Строка заголовков / групп» скрыты — меньше лишних кликов.
- Импорт: в сопоставлении колонок явнее подсказки про перетаскивание, колонка «Тип поля», заметная подсветка выбранной строки.
- Импорт: на шагах мастера единая навигация «Назад» / «Вперёд».
- Импорт: на шаге «Лист и структура» таблица файла и выбор типа структуры показаны равнозначно, со стрелкой перехода между ними.
- Импорт: конструктор сопоставления — поля слева и каталог колонок справа (drag-and-drop); группы «Из структуры» / «Добавленные свойства» со сворачиванием; доп. свойства через ту же модалку «Выбор свойств», что в форме материала.
- Виджет тегов / групп: блок подсказок компактнее («Доступные теги»), уже выбранные скрываются из списка.

- Импорт: при нераспознанных значениях на шаге «Запись» — таблица всех значений к записи; проблемные ячейки правятся по клику.
- Импорт: шаблоны маппинга (бывш. профили) хранят сопоставление колонок, тип структуры и общие теги партии; доступны сразу после загрузки файла на шаге настройки листа.
- Импорт: новые материалы получают тег `статус::на проверке`; канбан «Проверка импорта» — колонки «На проверке» / «Учрежден»; на дашборде — «Импорт к разбору».
- Импорт: на сопоставлении — блок «Теги для всех материалов» (существующий или новый; цвет правится на чипе); теги добавляются ко всем создаваемым материалам партии.
- Импорт: на шаге «Запись» — предупреждение о совпадениях по названию (пропуск, префикс или постфикс); перезапись существующих материалов запрещена.
- Импорт: на шаге «Запись» — дублирование кнопок «Игнорировать» и «Записать» под таблицами; ручные правки ячеек подсвечиваются синим (жёлтые предупреждения и зелёные исправления — как раньше).
- Закладки страниц: в шапке «В закладки» (название, иконка и цвет); на пунктах бокового меню кнопки нет; уже закреплённый URL — «В закладках»; список в сайдбаре.
- Типы структур: карточки в списке; клик по типу открывает записи, шестерёнка — управление.
- Записи структуры: таблица материалов типа с колонками полей структуры (полные заголовки с единицами); горизонтальный скролл, название и код закреплены слева; поиск как у материалов (в т.ч. по тегам); на карточке записи — «Развернуть» для связанных материалов.
- Дашборд: «Незавершённый импорт» переименован в «Продолжить импорт».

### Changed

- Профиль: секрет токена API — одноразовый flash (не открывается снова при возврате на страницу); закрыть окно можно только после копирования; таблица токенов в стиле остальных списков.
- API v1: создание скана принимает `tag_names`; при заголовке `X-Client: KeenetiX` автоматически ставится тег `источник::KeenetiX`; в ответе скана поле `tags`.
- Брендинг: в шапке логотип KEENETICA LAB; подпись бренда в футере и title — Keenetica Lab.
- KeenetiX desktop channel: «Открыть в KeenetiX» через API (без `keenetix://`); активен последний desktop с токеном пользователя; индикатор в шапке.

### Fixed

- Структуры: таблица материалов типа показывает только материалы активного пространства (без общих из других), чтобы поиск по тегам и смена пространства работали согласованно.
- Бэкапы: восстановление из файла на сервере (`/backups`) без upload через браузер; проверка сигнатуры `PGDMP`.
- Бэкапы: ручной дамп сохраняется на том и скачивается отдельной ссылкой (повтор при обрыве «Сайт недоступен»).
- Бэкапы: сброс «зависших» запусков со статусом «Выполняется» (часто после restore) и кнопка отмены на странице бэкапов.
- Бэкапы: в Docker-образе `postgresql-client-18`, чтобы `pg_dump` совпадал с Postgres 18 на стенде (раньше клиент 16 давал `server version mismatch`).
- Импорт: создание неизвестных значений справочников выполняется в одной транзакции с материалами (при ошибке записи «сироты» в справочнике не остаются).
- Импорт: значения вида `900/2200 Н/50мм` не принимаются молча как одно число — уходят в ручную правку.
- Импорт: при ошибке в одном поле на «Запись» успешно исправленные ячейки сохраняются и больше не показываются как неисправленные.

## [0.2.0] - 2026-07-22

### Added

- План и ADR: workspaces, RBAC (admin/manager/operator), GitLab-подобный sidebar ([docs/architecture/workspaces-rbac.md](docs/architecture/workspaces-rbac.md)).
- Приложение `apps.workspaces`: модели Workspace/Membership, middleware, login/logout, выбор пространства, sidebar, права manager/operator, UI администрирования пользователей и настроек WS.
- Зависимость `django-guardian`; команда `migrate_to_workspaces` для переноса prod-данных в Legacy WS.
- Форма материала: модальный выбор типа структуры; sticky-кнопки сохранения на длинных формах.
- Автоподстановка нового свойства в форму материала после создания из справочника.
- Образцы наследуют параметры структуры материала (просмотр и форма).
- Ссылки на материалы в пространстве (`WorkspaceMaterialLink`) вместо полного клонирования; кнопка «Добавить в пространство».
- Создание материала «на основе»: подстановка полей, свойств, параметров структуры, слоёв и тегов из шаблона (без образцов и файлов); шаблоном может быть любой материал пространства.
- Профиль пользователя: редактирование имени, e-mail и смена пароля; создание учётных записей — только администраторам.
- Тип свойства «Материал»: значение — ссылка на другой материал (выбор через picker при добавлении свойства к материалу).
- Тип свойства «Выбор из списка»: варианты задаются в справочнике свойства; на форме материала значение выбирается из стилизованного списка; в типе структуры такое свойство добавляется как `ChoiceField` (не как строка) с сохранением вариантов.
- После создания SQL-таблицы типа структуры можно добавлять новые поля (колонки); удаление и изменение существующих полей запрещены.
- Теги: цвет (#RRGGBB), описание, архив; scoped-названия `область::значение` с взаимоисключением по области; GitLab-подобный вид меток.
- Числовые свойства материалов и образцов: режимы «точное», «диапазон» и «± погрешность»; в справочнике — поле «знаков после запятой».
- Десятичные поля типов структур: те же режимы значения (точное / диапазон / ±); команда `migrate_structure_decimal_ranges` для существующих таблиц.
- Импорт материалов: CLI `import_materials` и UI-мастер с обязательным типом структуры, маппингом колонок в поля структуры (SQL) и доп. свойства справочника (без автосоздания Property), политикой уникальности, черновиком и шаблонами маппинга.
- Импорт: значения `material_link` и полей структуры `MaterialLink` — по коду, уникальному названию или UUID (в т.ч. на материалы из того же файла).
- Импорт XLSX: объединённые ячейки разворачиваются — значение из левой верхней ячейки копируется во все строки/столбцы объединения.
- Импорт: режим **построчной** записи выбирается сразу после сопоставления колонок (равноправно с пакетным черновиком).
- Импорт: из ячеек вроде `4050/ 50мм` и `12,5 мм` извлекается число (единицы / ширина полоски отбрасываются).
- Импорт: запись вида `0,27+0,035` / `12+1 /м` читается как ± допуск (как в больших таблицах Excel без символа ±).
- Откат последнего импорта: кроме `DEBUG` можно включить `IMPORT_BATCH_UNDO=true` на стенде.
- Поле `Material.import_source_filename` и фильтр «Источник импорта» в списке материалов (материалы из конкретного файла импорта).
- Импорт: демо-файлы большой таблицы Excel/CSV (`materials_wide_demo`) и ссылки скачивания на шаге загрузки.
- Групповое удаление в списке материалов: кнопка «Выбрать», чекбоксы, подтверждение и удаление выбранных (с учётом прав и защиты слоёв).
- Групповое удаление также в списках тегов, образцов, свойств и справочников материалов (та же кнопка «Выбрать»).
- Подтверждение удаления — диалог на той же странице (вместо отдельной страницы подтверждения), в т.ч. для группового удаления.
- Глобальные справочники материалов (производитель, доступность, технология): поля на материале, фильтры списка, цели импорта; UI «Справочники» и админка.
- Импорт: опция «создавать неизвестные значения справочников» с отчётом и защитой от дубликатов (имя/код).

### Changed

- `Material.name`: лимит длины увеличен с 200 до 1000 символов (длинные названия-укладки из больших таблиц Excel).
- В типе структуры убрана кнопка «Ссылка на материал»: ссылка на материал добавляется только через свойство справочника (`material_link`) в пикере «Добавить».
- Material/StructureType/Sample/Scan: поля `home_workspace`/`workspace`, видимость и фильтрация по активному пространству; код уникален в пределах WS.
- Карточка свойств: единица в отдельной колонке «Ед.» рядом со значением (значение справа, единица слева), блок прижат к названию свойства.
- При создании свойства из формы материала черновик формы сохраняется и восстанавливается после возврата.
- «Создать на основе»: код и название копируются из шаблона без префикса; дубликат кода в пространстве и среди общих материалов блокируется при сохранении.
- Карточка материала: ссылка «Открыть материал» вместо «Открыть образец».
- Точность десятичных полей структуры по умолчанию — 4 знака после запятой.
- Общие и ссылочные материалы: образцы и вложения показываются из домашнего пространства материала (readonly).
- Формы входа и администрирования пользователей: единый Bootstrap-шаблон полей.
- Цвет типа структуры — свободный hex с палитрой (вместо фиксированных tone-классов).
- Теги: inline-редактирование на карточках материала, образца и скана (только в своём пространстве); цвет общих тегов на бейджах; назначение тегов в workspace сущности.
